# 经验记录：C 组 绘制 / 原生文本判定（2026-11-26）

## 未读破折号被画成已读颜色（#1119）
- 现象：死に逝く君、館に芽吹く憎悪，未读句「込み上げて来て――――」字是白色，破折号是已读黄色
- 原理：破折号不画字形，改画一条线，线色在 token 插入时从字形填色取一次就冻结；整句的已读/未读状态（body.tome-line-read / tome-line-color）在 token 之后才到，线一直留着上一句的颜色
- 修法：读颜色时先摘掉 megulit-dash 类和行内透明填色再取，body / html 的 class、style 变了就重新取一遍。所有游戏、所有绘制路径共用
- 教训：任何「插入时取一次计算样式」的写法，都要想清楚这个样式之后会不会被整句状态改掉

## 原生台词被当成选项，给原生字注音+翻译（#1118）
- 现象：死に逝く君，血塗れの男 的每句台词，旁路流（KiriKiri2）提前 4 ms 送来「X…」　「X…」　，主流随后送「X……」；省略号个数不同，新行到达时 reset 没认出这是同一句，候选留下，和名牌「血塗れの男」凑成两项去 OCR，OCR 两个都找到 → 选项层盖在游戏原文上，隐藏也放开
- 修法（内核 ChoiceCapture，所有引擎受益）：新行到达时，按去标点/省略号后的字母比对、或「引号开头的子序列」判定是同一句就丢掉；同一时刻这一句的说话人名牌不算选项；同一批里「男男」这种单字叠写且是另一个候选结尾的，是逐字画名牌的最后一帧
- 教训：旁路流和主流的同一句往往只差标点（…/……、―/――），比对一律用去标点后的文字

## 译文最后一两个字单独换行（#1122）
- 现象：死に逝く君，「最後の最後まで、生に縋ろうとしていた。」的译文「…抓住生的希」换行后「望。」独占一行
- 原理：锚定模式下译文宽度 = 日文块宽度（2026-11-20 CHAOS;CHILD 定的对齐规则），译文比日文多一两个字就剩个尾巴
- 修法（点读层共用排版）：最后一行只是短尾巴（≤2.6 个字宽或 ≤18% 行宽）时，按尾巴宽度加宽译文，字号不变，上限到游戏客户区边缘；加宽后行数没减少就还原。真需要两行的长译文不受影响
- 教训：「对齐日文宽度」这类规则要给溢出一两个字的情况留余量，不然产品要求的「显示器有地方就不挤压」被反向违反
