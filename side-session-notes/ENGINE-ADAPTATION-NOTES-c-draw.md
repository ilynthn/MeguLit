## 原生台词被当成选项，给原生字注音+翻译（#1118）
- 现象：死に逝く君，血塗れの男 的每句台词，旁路流（KiriKiri2）提前 4 ms 送来「X…」　「X…」　，主流随后送「X……」；省略号个数不同，新行到达时 reset 没认出这是同一句，候选留下，和名牌「血塗れの男」凑成两项去 OCR，OCR 两个都找到 → 选项层给游戏原文注音+翻译（同一时刻 krkr 隐藏也刚好被收回，见下条）
- 修法（内核 ChoiceCapture，所有引擎受益）：新行到达时，按去标点/省略号后的字母比对、或「引号开头的子序列」判定是同一句就丢掉；同一时刻这一句的说话人名牌不算选项；同一批里「男男」这种单字叠写且是另一个候选结尾的，是逐字画名牌的最后一帧
- 教训：旁路流和主流的同一句往往只差标点（…/……、―/――），比对一律用去标点后的文字

## 点读层出来后被收回、原生字画出来；下一句原生字先出 → 双重叠字（#1124 #1125）
- 现象：死に逝く君，血塗れの男 的每句（行 100129 100135 100138 100211 100221-100223）出字 0.3 s 后 engine-draw.log 出现同一行 n=0 hidden=0，hook-events「placement gone: cleared by the game」，随后「check visible 游戏原文仍然可见」；下一句开头是 hidden=0（原生先画）1 ms 后才 hidden=1
- 原理（按日志推断，未实机复现）：KiriKiri TextRender 路径的隐藏 tick（script.inc trHide）在「当前消息层不再是这一层 / 这一层暂时不显示」时收回整行（报 n=0、恢复 textLayer 不透明度）；同期状态行 hid0 empty0 blank0 link=0，排除了 trDone 的各条收回路径，只剩 trHide。文字窗口随后带着同样的文字回来、但不重新排版，于是原生字一直露着，下一句也从不透明开始画
- 修法（KiriKiri 引擎层 + 内核小改）：trHide 收回的行先暂存；这一层重新成为显示中的当前层、且 getCharacters 排出的文字完全一样时，重新隐藏并用同一行号再报一次。新排版、MessageLayer.clear、其他任何收回都丢弃暂存；有链接的层、读模式不恢复。OverlayPlacement 对「gone 之后同 id 同文字又 hidden」发 regained，点读层据此撤销 goneText 重新摆位。另加 trwhy 计数 away/switch/unshown/resume，下次日志能直接看出是哪种
- 教训：「收回」和「彻底没了」要分开：窗口临时让位不等于这一句结束
