# 架构、归属与修复位置

本文件由 AGENTS.md 拆出，条文原样保留，与 AGENTS.md 同样有约束力，冲突时以 AGENTS.md 为准。

## 项目简介

MeguLit 是一款运行在 Windows 10/11 x64 上的日语学习工具，面向通过日文原版视觉小说（galgame）学习日语的用户。用户照常运行游戏，MeguLit 通过注入游戏进程的钩子直接读取正在显示的台词，不使用截图或 OCR，也不另开阅读窗口。它在原文旁绘制注音和译文，并提供点读查词、AI 讲解、游戏原声或本地语音朗读、生词本、Anki 制卡与复习、五十音和语法课程，以及游戏库管理。界面提供简体中文、英文和日文。

运行时由以下部分组成：

- **桌面宿主**：`desktop/` 中的 Tauri 2 程序（Rust，WebView2），负责启动本地 Node 服务并承载界面窗口。
- **本地服务**：`services/` 与 `core/`，承担全部业务逻辑，包括游戏识别、文本处理、读音、翻译、查词、Anki 和设置。
- **原生组件**：`native/` 中注入游戏的 C++ 钩子 DLL（基于 LunaHook 等），以及与之通信的 C# 辅助程序（`HookBridge`、`GalWindowBridge` 等）。
- **界面**：`web/` 为主界面，`web/reader/` 为覆盖在游戏上的阅读层。
- **适配数据**：`The Seed/` 存放每部游戏、每个发行版本的差分数据。数据只含配置，不含代码。
- **在线服务**：`relay/` 是 Cloudflare Worker，负责诊断回传、共享适配和适配包分发；`site/` 是官网与下载镜像。

产品定位与设计约束见 [PRODUCT.md](../PRODUCT.md)，用户说明见 [README.md](../README.md)。本项目以 GPL-3.0-or-later 发布。

## 产品原则与权限

- 游戏优先。覆盖层不得遮挡游戏操作、抢夺焦点或造成闪烁。
- 不修改游戏数据。不得改写游戏文件，不得以 OCR 遮盖原文。
- 保护用户的存档和 Anki 进度。涉及这些数据的改动必须说明旧数据如何迁移，以及失败时如何保留原数据。
- 不引入前端框架，使用原生 JS/CSS。已有的 CSS 类名、存储键和原生 ABI 必须保持兼容。
- 界面文字须同时提供中、英、日三种语言。修改一种语言时，三种一并修改。
- 以下事项须先取得维护者决定，再进行实质性实现：上传或共享用户数据的新途径、新的网络服务、对游戏进程的新注入或新写入方式、签名与发布流程、适配包格式。早期提案和草稿 PR 欢迎提交，但不等于获准合并。
- 发布版本只由维护者执行。

## 分层与修复位置

因游戏而异的行为一律表示为配置键，每部游戏以一份冻结的设置运行。权威说明见 [docs/diff-layers.md](diff-layers.md) 中「当前权威接口」一节。

修复须放在能覆盖问题的最低层：

1. 仅影响一部游戏：修改该游戏自己的差分（`The Seed/<引擎>/<作品>/` 或 `core/profiles/games/`）。
2. 影响同一引擎的多部游戏：修改引擎层（`core/profiles/engines/<引擎>.cjs`、该引擎的绘制钩子或剧本读取器）。
3. 内核需要新行为：先在 `core/profiles/defaults.cjs` 新增键，默认值保持原有行为，再由需要的引擎或游戏设置该键。引擎文件和游戏文件只能设置 `defaults.cjs` 中已存在的键。
4. 不得为单部游戏修改内核或共享代码。曾有两部 KiriKiri 作品因修复写入共享代码而互相破坏。

此外：

- 读模式只能由用户手动开关。任何自动判断（文字特效判据、自检、校准、差分状态、冷测试）只能记录诊断和显示提示，不得切换渲染模式。
- 差分数据为纯数据，不得包含本机路径、用户名或其他个人信息。

## 架构与归属

| 目录 | 职责 |
|---|---|
| `desktop/` | Tauri 宿主，启动服务并管理窗口 |
| `services/` | 业务逻辑；`services/original-engines/` 为各引擎剧本读取器 |
| `core/` | 内核：钩子、窗口、覆盖层定位、读音、翻译、游戏指纹；`core/profiles/` 为分层配置 |
| `web/` | 主界面；`web/reader/` 为阅读层 |
| `native/` | C# 辅助程序与注入游戏的 C++ DLL |
| `relay/`、`site/` | 在线服务与官网，各有独立的依赖和测试 |
| `setup/` | 安装器 |
| `tools/` | 构建、测试、发布与维护工具 |
| `validation/` | 测试 |
| `The Seed/` | 游戏差分数据 |
| `preserved/` | 保留的历史代码，不在此开发新功能 |

- 每一种解释和每一项资源须有唯一的归属方，其他使用者调用归属方的结果，不得各自重新解析原始数据。例如游戏指纹只由 `core/game-print.cjs` 计算，应用、探针、差分工具和 relay 共用同一实现。
- 阅读层中的生成模块只能通过 `tools/*.cjs` 修改，不得手工编辑生成结果。
- 修复缺陷时，须检查兄弟路径（其他引擎、其他入口、主界面与阅读层）是否存在同一问题，并在同一 PR 中修复或在 PR 中说明。
- 被取代的旧实现、别名和冗余测试须在确认无使用方后一并删除。
