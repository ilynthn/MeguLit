# Yui 启动诊断

桌面主程序解析安装根目录后，在单实例协调、依赖检查、后台服务和 WebView 初始化前建立本机会话。Windows 加载器在 Rust main 之前拒绝映像、找不到 DLL 或被系统策略拦截时，Yui 没有执行机会，需要 Windows 事件查看器或安装器日志。安装目录不可写时也无法留下本机记录

每次启动写入 logs/yui 下独立的阶段日志。文件名含本机启动时间和进程号。每类事件最多记录八次，保留最近十二次启动。单游戏诊断包含当前桌面会话，全应用诊断包含保留的启动记录。正常退出记录 closed，明确的初始化错误记录失败阶段，未记录终点的旧会话按中断处理。中断本身无法确定是程序崩溃、强制结束还是断电。前端绘制记录来自 WebView 帧回调，不代表人工验收

反馈面板的 Yui 开关默认关闭。适配贡献授权涵盖游戏剧本和程序样本，手动反馈只授权该次提交。开启 Yui 后，后台仅发送故障类型、上一阶段、从启动算起的毫秒数以及按本机授权密钥生成的匿名去重编号。人工点读标记、错误原文、路径、会话文件名和诊断 ZIP 均排除在自动消息外。关闭会中止本机发送并清空待发队列，再次开启使用新的密钥与时间界限。退出后，下次后台服务可用时继续读取本地记录

客户端最多保留 64 份待发报告。Relay 将报告编号作为 D1 主键，按故障类型归并并累计次数。半小时任务将汇总写入带有 yui-report 和 diagnostics 标签的 [Yui] issue。数据库迁移和 Worker 部署属于上线步骤。测试使用本地 SQLite 和模拟 GitHub 接口

2026-11-26 补充：服务进程和游戏 Hook 也往同一份会话日志写阶段（core/yui-journal.cjs：Hook 组件缺失、Hook 报错、游戏还在时 Hook 自己退出）。桌面端在 WebView 建好后等页面加载和主窗口显示，超时各记一次（document-timeout、reveal-timeout），原生 panic 记 native-panic。前端未处理的 Promise 拒绝按种类分开：服务错误码（frontend-rejection-service）、取消的动画或请求（frontend-rejection-abort）、其余（frontend-rejection）。拒绝和脚本错误的错误码、错误名和第一处脚本位置以「~阶段」行留在本机日志里，只进手动诊断包，自动消息仍只有故障类型、上一阶段、毫秒数和匿名编号

冷测试、自动适配这类不经过桌面程序的运行可以用 core/yui-run.cjs 在自己的运行目录写同样格式的阶段记录（yui-run.log），失败时记下失败阶段和原因，没写终点的按中断处理。这份记录只在本机，不经过 Yui 开关，也不发送
